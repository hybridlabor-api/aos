## Summary

- **What:** `stashctl list` and `stashctl prune` accept `--json` and return exit codes 0 (ok), 2 (usage) and 3 (nothing to do).
- **Why:** CI scripts parsed the table output with `awk` and broke whenever a column changed.
- **Scope:** output formatting only. Storage format and the default human output are unchanged.

### Most important change: list output

<Compare>
<Before>

```text
$ stashctl list
ID    AGE   SIZE
a1f3  2d    4.1M
b7c9  9d    0.8M
$ echo $?
0
```

</Before>
<After>

```text
$ stashctl list --json
[{"id":"a1f3","ageDays":2,"bytes":4300800},
 {"id":"b7c9","ageDays":9,"bytes":838860}]
$ echo $?
0
```

</After>

## Decisions

<Decision title="JSON shape" question="Which shape does --json print?" options={[
  { id: "array", label: "One JSON array per command", detail: "Simple to read with jq, one document per run.", recommended: true },
  { id: "ndjson", label: "One JSON object per line", detail: "Rejected: streams well, but every consumer we know reads the whole output anyway and would need a line splitter." },
]}>

An array keeps the output valid JSON for any parser. If lists grow beyond memory, add `--ndjson` later as a separate flag.

</Decision>

<Decision title="Exit code for an empty prune" question="What does prune return when nothing was removed?" options={[
  { id: "three", label: "Exit 3", detail: "Scripts can tell a no-op from a real prune.", recommended: true },
  { id: "zero", label: "Exit 0", detail: "Rejected: hides the no-op, and CI cannot branch on it without parsing output." },
]}>

Exit 3 is documented in `--help`. Anyone relying on 0 for an empty prune must update their script.

</Decision>
